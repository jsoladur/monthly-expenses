## [Unreleased]

### Added
- Month incomes (UC-07): add / edit / hard-delete of month-scoped income rows (PRD UC-09 / §6.5 / C15 / §7.8). New `userId`-first repository `src/server/repositories/income.ts` (`insertIncome` / `findIncomeById` / `updateIncome` / `deleteIncome` / `listIncomesForMonth`); `month_income` has no direct `user_id` column so every read/write joins on `month` with `month.user_id = userId` (PRD §5.1). `update` uses PG `UPDATE ... FROM month WHERE month.user_id = userId` in one statement; `delete` uses a raw `sql` template (Drizzle's PG delete builder doesn't expose `.using()`) so the WHERE clause enforces tenancy in a single statement — PRD C15 / §13 hard delete on month-scoped money rows. New service `src/server/services/incomes.ts` owns `addIncome` / `editIncome` / `deleteIncome` / `listIncomesForMonth`. Domain rules: the target category must be an ACTIVE income-kind row (ExpenseCategoryError / InactiveCategoryError / CategoryNotFoundError — the latter is reused from the categories service so the action layer maps one i18n key across both surfaces); the parent month is resolved via `findMonthById` so a missing month surfaces as `MonthNotFoundError` BEFORE the user picks a category (PRD §5.1). Money round-trips through `parseAmount` → integer cents → `formatCents` per ARCH §8 / ADR-5; negative amounts allowed (PRD UC-16). Hard delete on every remove (PRD C15). Server actions `addIncomeAction` / `editIncomeAction` / `deleteIncomeAction` in `src/actions/incomes.ts` follow the Zod-parse → `requireUserId()` → service → `revalidatePath` pattern (ARCH §5 rule 3) and translate domain errors into `IncomeActionError = "expenseCategory" | "inactiveCategory" | "categoryNotFound" | "incomeNotFound" | "monthNotFound" | "amountFormat" | "validation"`. The actions carry the active `(year, month)` from the caller's URL so revalidation targets the exact workspace route. The UI replaces the UC-06 "coming next" placeholder with a real `IncomesScreen` client (`src/app/[locale]/months/[year]/[month]/incomes-screen.tsx`) — receives `initialIncomes` (serialized with `amountCents` integer cents, ADR-5 / ARCH §8) + ACTIVE income categories for the picker + the full category map for historical lookups (so a row whose category was later deactivated still shows its name + an inactive-note caption). The row toggles into an inline edit mode (`centsToInputString` seeds the AmountInput) and offers Delete with a `window.confirm` prompt. New helper `centsToInputString(cents)` in `src/i18n/format.ts` is the inverse of `formatMoney` for the integer-cents part so the edit form rehydrates the wire string from the stored cents. PRD §15 #5 covered by `tests/integration/incomes.test.ts` (11 cases — happy create, negative amount, expense category rejected, inactive category rejected, unknown category rejected, edit replaces all fields, hard delete + row gone, edit/delete on missing row, historical income keeps rendering after category deactivate, two-tenant isolation including cross-tenant edit/delete, income CRUD never touches the template table) and `tests/e2e/incomes.spec.ts` (chromium + mobile-safari, 6 cases — add → edit → delete happy path with DB row-count check, no-active-categories empty state, Spanish variant with `Añadir`).
- Month creation, cloning & home navigation (UC-06): manual month creation with the one-time template clone (PRD UC-08 / UC-14 / UC-19 / C6 / C12 / §7.8). New `userId`-first repository `src/server/repositories/month.ts` (`findMonthByPeriod` / `insertMonth` / `listMonths` / `insertClonedLines` / `listMonthFixedLines` / `listMonthIncomes` / `listMonthActuals`); every function filters by `userId` per ARCH §5 rule 1. New service `src/server/services/months.ts` owns `createMonth(userId, year, month)` — pre-flight duplicate check via `findMonthByPeriod`, then `db.transaction(async tx => ...)` opens ONE tx, inserts the `month` row, fetches the user's ACTIVE templates via `listActiveTemplates(userId, tx)`, and bulk-inserts one `month_fixed_line` row per template with `remaining_amount = original_amount = template amount` and `origin = 'cloned'` (PRD C17, §7.8). `month_user_period_uk` backstops duplicate creation (PRD UC-08) and surfaces as `DuplicateMonthError`. Incomes are NEVER cloned (PRD §7.8); months never sync with templates or other months after creation — verified by an integration test that snapshots month money-row counts around a full template-edit + deactivate cycle. Server action `createMonthAction` in `src/actions/months.ts` follows the Zod-parse → `requireUserId()` → service → `revalidatePath('/[locale]', 'page')` pattern (ARCH §5 rule 3) and translates `DuplicateMonthError` into `{ ok: false, error: "duplicate" }`. Cookie helpers (`readLastOpenedMonthCookie` / `setLastOpenedMonthCookie` + the `LAST_OPENED_MONTH_COOKIE` constant + `LastOpenedMonth` interface) live in `src/server/cookies/last-opened-month.ts` (NOT inside `actions/months.ts`) because Next 16 forbids non-async exports from `"use server"` files. The home page (`src/app/[locale]/page.tsx`) reads the cookie, re-validates against the DB, and redirects to the matching workspace if it exists (PRD UC-14); otherwise renders the empty-state create form (with PRD §19 "Nothing is created automatically" copy) or the month list (newest first) with a collapsible create form. The workspace (`src/app/[locale]/months/[year]/[month]/page.tsx`) is a read-only skeleton that renders the cloned reserved lines grouped by kind (committed first, then estimated) with `formatMoney(parseAmount(remaining_amount), currency)` labels; Incomes + Actuals render "coming next" placeholders for UC-07/08. Out-of-range year/month route segments surface as 404 (range validation lives in the page's RSC guard). Direct visits to the workspace touch the resume cookie via a tiny `MonthTouchClient` (`document.cookie` after mount) because Next 16 also forbids `cookies().set()` from RSC bodies; the cookie is a UX hint, not a security boundary (PRD §5.4). PRD §15 #3 + #4 + #18 covered by `tests/integration/months.test.ts` (10 cases — empty create, duplicate rejection, full clone snapshot for committed + estimated, inactive templates excluded from clone, no-cross-month sync, no-cross-tenant leakage, atomicity on duplicate, sorted list, month-not-found) and `tests/e2e/months.spec.ts` (chromium + mobile-safari, 6 cases — empty-state → form create → cloned lines → cookie resume → second month newest-first list view → duplicate inline error → Spanish variant).

### Changed
- Split `src/components/amount-input.ts` (helpers only) into `src/components/amount-input-helpers.ts` because the two-file split (`.tsx` + `.ts`) confuses the path resolver; `AmountInput` now lives unambiguously at `src/components/amount-input.tsx`. `AmountInput` also accepts an `id` prop so callers can link `<label htmlFor>` and target the underlying `<input>` from tests.

### Added (previous slices)
- Profile settings screen (UC-04): display-only currency label (PRD C9, UC-15, §7.6). New `userId`-first mutator `updateCurrency(userId, currency, tx)` in `src/server/repositories/profile-settings.ts` writes ONLY `profile_settings.currency` + bumps `updated_at` — the `char(3)` column type is the DB-layer defense in depth behind the Zod `^[A-Z]{3}$` regex in `currencySchema`. New service `src/server/services/settings.ts` owns the domain rule (ISO 4217 alpha-3, otherwise `InvalidCurrencyError`) and verifies the tenant actually has an `app_user` row before the update — so a missing profile row surfaces as `ProfileSettingsNotFoundError` rather than a silent no-op. New server action `updateCurrencyAction` in `src/actions/settings.ts` follows the Zod-parse → `requireUserId()` → service → `revalidatePath('/[locale]/settings', 'page')` pattern (ARCH §5 rule 3) and revalidates BOTH the settings page AND `/[locale]` so the home surfaces the new label on next render. New display helper `formatMoney(cents, currency)` in `src/i18n/format.ts` returns `<sign><amount> <LABEL>` with exactly two fractional digits and no grouping separator (PRD C9: dot-decimal in BOTH locales, so display mirrors input); throws on non-integer cents or non-3-letter labels (ADR-5, ARCH §8). New settings screen at `/[locale]/settings` (screen 8) is an RSC shell that loads the row, renders a `formatMoney` preview block (positive / zero / negative sample amounts in the active currency so the user can see the change before saving), and hands off to a client `SettingsForm` that uses React 19 `useActionState` + a native `<select>` for the picker — successful save bumps `formKey` so the select's `defaultValue` re-reads from the freshly-revalidated `currentCurrency` prop, and the confirmation surfaces through an `aria-live="polite"` region. i18n bundles extended with `settings.currentLabel`, `settings.preview.*`, `settings.actions.save`, `settings.status.saved`; existing `validation.currencyInvalid` is reused for the keyed error. PRD §15 #15 + the 2-decimal formatting invariant for every amount-rendering slice covered by `tests/unit/format-money.test.ts` (8 cases including the full `numeric(14,2)` range and rejection of non-integer cents) and `tests/integration/settings.test.ts` (7 cases — EUR default, single-row update, no-other-money-row-touched, tenant isolation, unknown-user `ProfileSettingsNotFoundError`, invalid codes rejected, repeated updates keep the row count at 1). Playwright e2e `tests/e2e/settings.spec.ts` (chromium + mobile-safari) reuses the auth-bypass helper from UC-03 and asserts the EUR → USD label swap in both the preview block and the live DB row, plus the Spanish variant.
- Fixed/estimated templates catalog (UC-05): per-user catalog of `committed` and `estimated` templates that are CLONED into a new month exactly once at month creation (PRD C17, §6.3, §7.8). New `userId`-first repository `src/server/repositories/template.ts` (`listTemplates` / `listTemplatesByKind` / `listActiveTemplates` / `listActiveTemplatesByKind` / `findTemplateById` / `insertTemplate` / `updateTemplate` / `deactivateTemplate` / `reactivateTemplate`); the `listActive*` family is the clone-source query for UC-06 and EXCLUDES soft-deleted rows, while `listTemplatesForManagement` includes them so the user can scan history. New service `src/server/services/templates.ts` validates that the target category is an ACTIVE expense category (using `findCategoryById` from the category repo and reusing `CategoryNotFoundError`) and round-trips the amount string through `parseAmount` → integer cents → `formatCents` per ARCH §8 / ADR-5. Soft delete is `active=false, deleted_at=now()`; a double-deactivate is mapped to `TemplateAlreadyInactiveError` via the repo's `WHERE active = true` guard, and reactivate reverses it (also `TemplateAlreadyActiveError` on double-reactivate). Editing a template never rewrites month rows — verified by `tests/integration/templates.test.ts` #10 (snapshot of month money-row counts is unchanged around a full CRUD cycle). Server actions in `src/actions/templates.ts` follow the Zod-parse → `requireUserId()` → service → `revalidatePath('/[locale]/templates', 'page')` pattern (ARCH §5 rule 3) and translate domain errors into `TemplateActionError = "validation" | "incomeCategory" | "inactiveCategory" | "notFound" | "alreadyInactive" | "alreadyActive" | "amountFormat"`. ### Fixed
- Signed-in users landing on `/[locale]` were silently redirected back to `/[locale]/sign-in`, making the Google sign-in flow look broken. The home now renders a minimal signed-in confirmation (email + display name + sign-out) until UC-06 delivers the real month workspace.
- Auth.js `jwt` callback was reading the Google `sub` from `user.id`, which without an Auth.js DB adapter is a freshly-minted `crypto.randomUUID()` generated by `@auth/core`'s `handleLoginOrRegister` (see `node_modules/.pnpm/@auth+core@0.41.3/.../actions/callback/index.js:70-80`). The callback now reads the stable OAuth subject from `account.providerAccountId` (falling back to `profile.sub`), short-circuits when `token.userId` is already set, and the `session` callback writes the internal `app_user.id` onto `session.user.id` — so the home page (and every later repository call) sees the right tenant id.
